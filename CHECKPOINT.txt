МАСТЕР-ЧЕКПОИНТ ПРОЕКТА BOXING COACH

Этот документ — полное руководство по архитектуре проекта. Он создан для того, чтобы любой новый чат с ИИ мгновенно понял, как устроен код, и мог безопасно вносить изменения.

1. ОБЩАЯ ИНФОРМАЦИЯ
Стек: Vanilla JavaScript (без фреймворков), HTML, CSS, Supabase (база данных и авторизация), Chart.js (графики), jsPDF (экспорт PDF).
Архитектура: Модульная. Код разбит на 20+ маленьких файлов (модулей), каждый отвечает за свою задачу.
Хранение данных: Supabase (облако) + LocalStorage (офлайн-режим и кэш).
Версия Service Worker: boxcoach-v14.
Публикация: GitHub Pages (renatsherman.github.io/boxing-coach).

2. СТРОГИЕ ПРАВИЛА РАБОТЫ С ЧАТОМ (ВАЖНО ДЛЯ ИИ!)
- Пользователь не умеет работать с кодом и не использует VS Code. Все изменения делаются только через веб-интерфейс GitHub.
- КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО давать куски кода, писать "замени строчку" или "добавь функцию". Любой измененный модуль должен выдаваться ПОЛНОСТЬЮ от начала и до конца, готовым к полной замене файла.
- Если меняется несколько файлов, они должны быть пронумерованы: "Файл 1: ...", "Файл 2: ..." и т.д.
- Если меняются любые файлы, ОБЯЗАТЕЛЬНО нужно выдавать обновленный sw.js с новой версией кэша (v15, v16 и т.д.).
- После каждой правки ИИ ОБЯЗАН выдавать обновленный МАСТЕР-ЧЕКПОИНТ (этот текст), чтобы история изменений сохранялась для следующих чатов.

4. ПОДРОБНОЕ ОПИСАНИЕ МОДУЛЕЙ

ФУНДАМЕНТ (Ядро приложения)
config.js: Константы. Ключи Supabase, MAX_SCORE, дефолтные группы, defaultDB.
utils.js: Вспомогательные функции. Расчет возраста, даты, средние баллы, группы, toast, emptyAssess.
data.js: Ядро базы данных (DB), loadLocal, миграции, saveLocal. Переменная DB через var.
cloud.js: Работа с Supabase. Авторизация, saveData, слушатели online/offline, отложенная синхронизация.
attendance-data.js: Логика посещаемости. Группировка по сессиям, проверка статуса, внеплановые бойцы.
journal.js: Рекомендации. Анализ оценок бойца (слабые стороны) и подбор упражнений.

НАВИГАЦИЯ И РОУТИНГ
nav.js: Глобальные переменные app и state. Объект Modal. Экран входа (LockScreen). Главный роутер render(). Ждет DOMContentLoaded.

ЛОГИКА БОЙЦОВ
fighters-core.js: Создание нового бойца, загрузка/сжатие фото, базовые поля, модалка назначения тренировок.
assessments.js: Оценки по направлениям. Модалки, сохранение, отрисовка радара Chart.js.
measurements.js: Замеры. Добавление, удаление, отрисовка линейных графиков Chart.js.
fighter-detail.js: Экран карточки бойца. Собирает воедино оценки, замеры, бои, план работы и календарь.

ФУНКЦИОНАЛ
calendar.js: Два календаря. Месячный для бойца. Недельный для тренера (iOS стиль, свайпы дней, фиксированная высота).
attendance.js: Интерфейс отметки. Чек-листы, кнопки "Отметить всех", отправка текста. Адаптирован под мобильные (крупные чекбоксы).
reports.js: Отчеты за месяц. Считает тренировки, посещаемость. Верстка адаптирована под мобильные в виде карточек бойцов (таблицы убраны).
exercises.js: Справочник. Управление блоками упражнений и замерами.
pdf.js: Экспорт. Генерация PDF через jsPDF.

ИНТЕРФЕЙС (Экраны)
index.html: Шапка сверху, меню внизу (bottom-nav), адаптировано под айфон.
dashboard.js: Главный экран. Календарь тренера сразу под шапкой. Аккордеоны с последними тренировками и "требующими внимания". График и статистика внизу. Функция initSwipe() для свайпов.
compare.js: Сравнение двух бойцов. Таблица и два радара.
settings.js: Настройки. Имя тренера, группы, направления, экспорт/импорт JSON.

ТОЧКА ВХОДА
app.js: Экспорт/импорт базы JSON, инициализация (LockScreen.init, Cloud.init) и регистрация Service Worker. Ждет DOMContentLoaded.

5. ТЕХНИЧЕСКИЕ ПРАВИЛА И ПОДВОДНЫЕ КАМНИ
- onclick функции должны быть объявлены через window.openFighter = () => {}.
- var DB вместо let DB в data.js, чтобы emptyAssess не падал при инициализации.
- При любом изменении файлов нужно менять версию кэша в sw.js (v14 на v15 и т.д.).
- Сброс кэша: Ctrl + F5 на ПК. На iPhone — Настройки -> Safari -> Очистить историю и данные.
